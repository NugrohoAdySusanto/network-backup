🛡️ Why Single-Pass AEAD (AES-256-GCM)?

AES-256-GCM unifies stream encryption and 128-bit GMAC authentication in a single hardware-accelerated pass while binding the 16-byte NBG2 || Nonce AAD header. It requires zero block padding, permanently eliminating Padding Oracle Attacks.

⚡ Why Compress Before Encryption?

High-entropy ciphertext provides no repeating patterns for compression. Compressing before encryption yields maximum storage and transfer savings depending on device configuration text.

🔒 Why Direct-DEK Without Payload PBKDF2?

PBKDF2 (100k rounds) already protects human secrets in Database Vault (NBV1) and Manifest KEK (NBM1). Because the repository DEK is already a CSPRNG 256-bit key, applying it directly removes CPU throttling while retaining full 256-bit security.

Cryptographic Terminology Glossary:

Plaintext
Original unencrypted device configuration text, readable as plain UTF-8/ASCII.
Ciphertext
Encrypted high-entropy bytes unintelligible without the authentic symmetric key.
256-bit DEK
Random 32-byte Data Encryption Key wrapped inside repo_manifest.enc (NBM1).
Nonce (12B)
Random 96-bit CSPRNG value ensuring unique AES-GCM keystreams across identical configs.
GMAC Tag (16B)
128-bit Galois Field authentication tag verifying ciphertext and header integrity.
AAD (16B)
Additional Authenticated Data (NBG2 || Nonce) bound cryptographically to the tag.
Ceph RGW S3
Distributed object storage platform providing AWS S3 API-compatible bucket storage.
Fail-Closed
Security policy where decryption immediately aborts if authentication tags or magic headers fail.
